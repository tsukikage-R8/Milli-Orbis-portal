## 1. 企画概要・コンセプト

* **サービス名（案）：** Milli-Pro Goods Archive & Finder（仮）
* **コンセプト：**
「ミリプロの“過去・現在・未来”のすべてのグッズ情報を集約し、推し活をより便利に、より楽しくする総合ポータル」
* **位置づけ：**
ファンメイド（非公式）ならではの機動力と網羅性を活かし、公式の販売促進をサポートしつつファンコミュニティの活性化に貢献する情報プラットフォーム。
* **今回の決定事項（サマリ）：**
  * 画像はリポジトリに保存せず、Shopify CDN へのホットリンク継続（`data.js:51` / `script.js:1825` の現行方式を踏襲）
  * 実店舗マップはリアルタイム掲示板を見送り、**B案: Google Form → 手動精査 → `data/sightings.json` → Leaflet + OSM/地理院地図で表示** を採用（費用0円・APIキー不要・日本限定）
  * 2026-09-06決定: (1)ミリプロは受注期間・発送期間を同時明記するため両方必須表示 (2)「現在」ページに販売予定も含む (3)販売箇所は特設サイトから全件取得（提供待ち） (4)譲求は `want/have` フラグ＋定型文生成までに留める

## 2. 開発の背景と目的

1. **公式スタッフ（ミリちゃん）の発言への共感と課題解決**
公式Xアカウント（ https://x.com/Mil_Staff_/status/2096136975359373426 ）での「グッズの販売場所一覧がほしい」という発言を受け、ファンの「どこで何が買えるかわからない」という課題を根本から解決します。
2. **公式情報と二次流通・過去データの双方の補完**
公式側では掲載しにくい「過去の限定品データ」や「実店舗の目撃情報（キュレーション済み）」まで網羅することで、公式一覧と差別化された独自価値を提供します。二次流通の在庫保証はしない旨を明記し、事実の記録に留めます。

## 3. ターゲット層

* **新規ファン：** 「過去にどんなグッズが出ていたか」「今どこで買えるか」を知りたい層
* **コアファン：** 買い逃しを防ぎたい層、自分のコレクター状況を整理・共有したい層

## 4. 主な機能一覧（2026-09-06要望反映・5機能に再編）

> 全ページで `script.js:340 getOshi()` の推し設定を反映（ハイライト・デフォルトフィルタ）。見た目はタブ、実体は `member` タブ同様にHTMLを分割（ファイル肥大防止）。

### ①【現在】販売中グッズ一覧＋販売予定（検索・絞り込みの本丸） → `goods/current.html`

* **対象：** 現在販売中 (`period.orderTo >= jstNow()` または `permanent:true`) ＋ 販売予定 (`period.orderFrom > jstNow()` → 別セクション「近日販売予定」)。ミリプロは公開時に受注期間・発送期間を同時明記するため（2026-09-06確認）、両方を必須表示。
* **1グッズあたりの表示項目：** `image`（ホットリンク `cdn.shopify.com`） / `name` / `memberId` / `kind`（アクスタ/缶バッジ等 `GOODS_ICON:36` 準拠） / `category`（誕生日記念/周年記念/加入記念/TCS等で絞り込み） / `price` / `period:{orderFrom, orderTo, shipFrom, shipTo}` / `shop`/`place`（売っている場所） / `url`（公式商品ページ）。
* **検索・絞り込み（ファンが嬉しいもの）：** テキスト検索 + タレントごと (`MEMBERS:107`) + グッズの種類 (`kind`) + なんのグッズか (`category`) + 販売場所 (`shop`) + ソート「受注終了が近い順（`period.orderTo`昇順）」。推し商品は `is-oshi` ハイライト。UIは `script.js:415 navDrop` と同様のドロップダウン＋チップ。
* **カウントダウン・カレンダー：** `GOODS[].period.orderTo` を `COUNTDOWN:950` / `script.js:465 cdLeft()` に流用し、締切3日以内はバッジ表示。`script.js:943 gcalUrl()` / `974 icsEventUrl()` でワンタップ登録。
* **データ拡張：** `GOODS[]:50` に `id, category, period{orderFrom,orderTo,shipFrom,shipTo}, shop, place, venue, status` を追加。`index.html:204 #goods` カルーセルは `goods/current.html` へのハブとして維持。

### ②【販売箇所検索】都道府県→店舗検索 → `goods/shops.html`

* **コンセプト：** 大型チェーンの店舗検索のように、日本地図（SVGの都道府県パーツ）から都道府県を選ぶと、その地域でグッズを売っている店が絞り込まれる。
* **データ：** 新規 `data/shops.json`（`data/youtube.json` と同様に `fetch()`）。`{id, name:"アニメイト秋葉原本館", chain:"animate", prefecture:"東京都", address, lat,lng, gmapsUrl, goodsIds:["kono..."], collab:"イオン×ミリプロ"}`。特設サイトのリンク提供待ちのため、提供後に全件を同形式で取り込み。**ミリプロオフィシャルオンラインショップは全47都道府県に含める**（リスト先頭に常時表示）。
* **UI：** 上部に日本地図SVG（47都道府県クリック）＋ `chain` フィルタ → 下部に店舗カード（`gmapsUrl` で Google Maps に外部遷移、取扱中のグッズは `goods/current.html#id` へ遷移）。
* **地図は使わない：** 本ページはSVG＋リストで軽量にし、Leaflet本格マップは ③ に分離。

### ③【有志匿名マップ】目撃情報マップ（B案・Leaflet本格版） → `goods/map.html`

* **方針：** リアルタイム掲示板は見送り、**キュレーション型B案**を本ページのみで本格実装。
* **地図表示：** Leaflet.js (CDN, 42KB) + OpenStreetMap または国土地理院タイル `https://cyberjapandata.gsi.go.jp/xyz/std/{z}/{x}/{y}.png`（無料・出典明記のみ）。日本Bounds `[20,122]-[46,154]` に制限、初期中心は秋葉原UDX `35.705,139.774`。
* **保存：** `data/sightings.json` を手動PRで更新（`data/youtube.json` と同様に `fetch()`）。例: `{ "id":"20260905-001", "place":"駿河屋 秋葉原店", "lat":35.698, "lng":139.771, "item":"あくび50万人記念フルセット", "memberId":"akubi", "date":"2026-09-05", "source":"form", "status":"approved" }`。地図では `approved` のみを `L.markerClusterGroup` でクラスタ表示。ポップアップに免責＋公式ショップ誘導を併記。
* **投稿フロー：** サイト上にフォームは置かず「情報提供はこちら → Google Form」リンクのみ。Form項目: `店舗名`/`都道府県`/`目撃日`/`グッズ名（自由記述+memberId選択）`/`任意コメント`/`X連絡先（任意）`。運営が1日1回精査して `data/sightings.json` にコミット（PRレビューでモデレーション）。

### ④【過去アーカイブ】歴代全グッズ網羅 → `goods/archive.html`

* **対象：** これまでミリプロが販売してきた全グッズを可能な限り網羅。`data/goods-archive.js`（または `data/goods-archive.json`）に分離し、`data.js:50` の肥大化を回避。`current` と同一の検索UI（タレント/種類/category）を流用。
* **画像：** ホットリンク継続（`cdn.shopify.com`）。URL失効時は `GOODS_ICON:36` のSVGに自動フォールバック。
* **有志追加依頼：** Google Form（`goods/archive` 用）で「追加してほしい過去グッズ」を募集 → 運営が `data/goods-archive.js` にPRで反映。直接書き込みはさせない。

### ⑤【マイグッズ】所持管理 → `goods/mine.html`

* **機能：** 自分の持っているグッズを登録（チェック）すると、所持率％・未所持一覧を可視化。`scripts/fav-store.js:1 MilliFav` パターンを `MilliGoodsMine` として流用（`localStorage` + ログイン時は Firebase `firebase-init.js:1` に同期）。
* **推し反映：** 推しタレントのグッズを先頭にソート、所持率も「全体」「推しのみ」で切替。
* **譲求の扱い（2026-09-06決定：前者で留める）：** 金銭関与しない前提でもサイト内マッチングはトラブルリスクが残るため、**`want/have` フラグ管理＋定型文ツイート生成（`script.js:1974 shareXBtn` と同様）までに留める**。取引自体はXのDM等で当事者間に委譲し、掲示板的な公開マッチングは実装しない。

## 5. 画像・権利およびコンプライアンス運用方針

1. **画像のホットリンク運用と公式リンクの併記（決定事項反映）**
* 商品画像はリポジトリに保存せず、Shopify CDN (`cdn.shopify.com`) へのホットリンクで表示する（`341fad9` で導入済み、RepoはURL文字列のみ保持）。
* 画像表示時は必ず「引用元：ミリプロオフィシャルショップ（商品URL `GOODS[].url`）」への直リンクを併記し、購入導線を確保する。`onerror` で自作SVG (`GOODS_ICON`) にフォールバック。
* `data.js:34` のコメント「画像掲載はしない方針 §9」は、ホットリンク運用に合わせて「ホットリンク運用（保存せず参照）」に更新する。

2. **非公式・有志サイトの明記**
* `SITE_CONFIG.disclaimer` (`data.js:6`) と同様に「本サイトはファン有志による非公式データベースです」と全ページに明記し、公式サービスとの誤認を防ぐ。`goods.html` フッターにも再掲。

3. **免責事項の設置**
* 実店舗・二次流通（中古）の在庫情報については、「リアルタイムの在庫を保証するものではありません。来店前に各店舗へお問い合わせください」といった免責を地図ポップアップと一覧に常時提示する。

4. **問い合わせ窓口（お問合せフォーム/X）の設置**
* 権利者様（公式運営様）からの要請やユーザーからの情報修正要請に迅速に対応できる連絡窓口を常設する。ハンバーガーメニュー内に設置（実装は `goods.html` 完成後に追加）。

## 9. 追加改善提案（2026-09-06）

> 前回提案した8案を計画書に正式反映。簡単なものから順に実装する。

### P0: すぐ効くUXの摩擦（工数小・体感大）

1. **フィルタ状態のURL共有** – `current/archive/mine` の検索条件（`?q=&member=koma&kind=stand&sort=deadline`）を `history.pushState` でURLに反映。Xで「小廻こまのアクスタで絞った結果」をそのまま共有可能にする。現状はリロードでリセットされる。`script.js:943 gcalUrl()` のようにクエリ生成するだけで実現。
2. **在庫/締切の視覚的優先** – `current.html:186` の `残りX日` を `3日以内` は赤バッジ＋点滅（`style.css:482 liveBadge` の `livePulse` 流用）、`当日` は `本日終了` と明記。ファンが最も焦るタイミングを強調し買い逃し防止。
3. **マイグッズの空状態の導線強化** – `mine.html:140` の初回0件時に「持っているグッズがありません → 過去アーカイブから登録する」だけでなく、`current` の `︙→持ってる` で登録できることを示すオンボーディング吹き出し（3ステップ）を追加。初回登録率向上。

### P1: ファンが本当に欲しい機能

4. **通知 / リマインド** – `script.js:729 getReminders()` の配信リマインドを流用し、グッズの `period.orderTo` を `5日前/当日` に `Notification`。`current` の各カードに `🔔 締切を通知` ボタンを追加するだけで既存の `reminderWatcher` を流用可能。初回は権限文言を丁寧に。
5. **所持率の可視化と共有** – `mine.html:24 mine-bar` の `progress` を `have` のみにせず `have(青)/want(橙)` の積み上げにし、`Xで共有` 時に `og:image` として所持率画像を生成（`Milli Games` の診断結果画像と同様）してX拡散を狙う。`have/want` の色は `style.css:1197 member-card` の `--mc` を流用。
6. **販売箇所検索の現在地連携** – `shops.html:225` の都道府県選択に加え、スマホの `navigator.geolocation` で現在地から近い3件を `shopList` 先頭に `📍 近くのお店` として自動表示。`data/shops.json` に `lat/lng` が無いため、まず `animate.co.jp/shop` と `prtimes` の住所から手動で `lat/lng` を付与するデータ整備が前提。

### P2: 中長期の差別化

7. **アーカイブのタイムライン表示** – `archive.html:133` は現在グリッドのみだが、「3周年はいつ何が出たか」を振り返るには `History` (`data.js:1111`) のような縦タイムライン（`style.css:1522 timeline`）で年/メンバーでグルーピングしたビューが欲しい。`current` と同じフィルタで `timeline` と `grid` を切替可能にするとコレクター満足度が高い。
8. **データ鮮度の自動化** – 現在 `767件` は手動で `products.json` を取得して変換したが、`tools/` の `fetch` ワークフロー（`.github/workflows/fetch.yml`）と同様に、毎晩 `shop.milpr.com/products.json` を `cron` で取得し `data.js` を自動更新する `GitHub Actions` を追加。`まもなく終了` や `販売終了` のラグを無くす。`period.orderTo` の自動判定（`convert_goods3.py` の `orderTo < now`）をCIに組み込む。

### 実装順（簡単なものから）

* Step1: P0-1 URL共有 → P0-2 締切バッジ強調 → P0-3 空状態オンボーディング
* Step2: P1-4 通知 → P1-5 所持率積み上げ
* Step3: P1-6 現在地連携（データ整備後）→ P2-7 タイムライン → P2-8 自動化CI

各Stepは `goods/*.html` と `style.css`/`script` の編集で完結し、追加のAPIキーや課金は不要。
